# backend-compsoc

Compares recorded wildfires with NASA satellite fire detections. Given a point and a year, it checks on the fly whether there is an **anomaly** there and, if so, works out its intensity and details.

## Data

Two CSV files and a climate grid, read once at startup from `data/` (override with `DATA_DIR`).

The two CSV files in `data/` are synthetic: about 5,000 wildfires and 67,000 detections worldwide from 2010 to September 2026, generated by `scripts/synthesise_data.py` from the real UK data in `data/real/` (NASA FIRMS MODIS detections and London Fire Brigade incidents) and the climate grid. The script's docstring explains the model. To regenerate them, run `uv run python scripts/synthesise_data.py` from this folder. The output is the same each time for a given seed.

**`wildfires.csv`**: recorded events. Extra columns (like `name`) are ignored.

| column | meaning |
| --- | --- |
| `latitude`, `longitude` | centre of the fire |
| `date` | `YYYY-MM-DD` |
| `radius_m` | footprint radius in metres |

**`satellite_detections.csv`**: a [NASA FIRMS](https://firms.modaps.eosdis.nasa.gov/download/) export, used as is. Required columns are `latitude`, `longitude`, `brightness` (or `bright_ti4` for VIIRS), `acq_date`, `acq_time` (HHMM UTC) and `confidence` (0–100, or `l`/`n`/`h` for VIIRS). `frp` (fire radiative power, MW) is optional. `scan` and `track` set the pixel radius. Other columns are ignored.

**`real/koeppen_geiger.txt.gz`**: the Köppen-Geiger climate class of every 0.5° land cell, from [Kottek et al. (2006)](https://koeppen-geiger.vu-wien.ac.at/present.htm), gzipped but otherwise as published. Each class maps to a dryness from 0 (tundra, ice) through 0.3 (rain all year), 0.5 (a dry season), 0.7 (savanna) and 0.8 (Mediterranean) to 0.9 (steppe) and 1 (desert); see `src/dryness.py`. Without the file, nowhere counts as dry.

Rows that fail to parse are logged and skipped.

## Anomaly detection

`find_anomaly` in `src/anomalies.py` takes the queried point and year, the search radius, and the loaded wildfires, detections and dryness grid. It returns the anomaly found there, or `None`.

Settings come from environment variables or `.env`. They are `DATA_DIR`, `WILDFIRES_FILE`, `DETECTIONS_FILE`, `CLIMATE_FILE` and `QUERY_RADIUS_KM`.

## API

- `GET /api/get_all_points`: every recorded wildfire.
- `GET /api/request_anomaly?longitude=&latitude=&year=`: the anomaly within `QUERY_RADIUS_KM` (default 250 km) of the spot in that year, found on the fly: its middle, `radius`, `confidence`, `intensity` and `distance` from the spot (metres). If there is none, it returns the spot, confidence 0, intensity 0 and the search radius.
- `GET /api/leaderboard`: the five largest anomalies found through `request_anomaly` so far, by radius (then number of detections), each credited to its first finder. Held in memory, so it empties on restart. When a query finds an anomaly that makes the board, its response carries a `claim` with a token.
- `PUT /api/leaderboard/{id}/name` with `{"token", "name"}`: the finder names their entry, once (1–24 characters).

## Run

```sh
uv sync
cd src
uv run fastapi dev main.py --port 8001
```

Port 8001 matches `BACKEND_URL` in the frontend's `.dev.vars`.
